# session-history Specification

## Purpose

定义历史训练记录的查看、编辑与删除契约：记录页只列可用记录，残缺记录有明确去向，编辑既有记录不得静默失败，也不得丢掉旧版本遗留的动作级字段。

## Requirements

### Requirement: 历史列表只列可用记录并说明残缺去向
系统 SHALL 只把结构可用的历史记录列入历史列表；被过滤掉的残缺记录 SHALL 以可读的数量提示告知用户去向，不得让用户以为记录凭空消失。

#### Scenario: 存在残缺记录
- **WHEN** 本地存储中混有结构不可用的历史记录
- **THEN** 记录页只列出可用记录，并显示「有 N 条记录格式异常已跳过」的提示

#### Scenario: 全部记录都不可用
- **WHEN** 本地存储中的历史记录全部结构不可用
- **THEN** 记录页正常渲染并给出残缺提示，不出现未捕获异常

### Requirement: 记录详情可查看并可编辑
系统 SHALL 提供记录详情弹层，展示训练日、日期、组数、容量、训练级 RIR 与疼痛、备注以及每个动作的逐组数据。

#### Scenario: 打开记录详情
- **WHEN** 用户点击历史列表中的某条记录
- **THEN** 弹层展示该记录的训练日、日期、组数、容量与逐组数据

### Requirement: 训练日已不在计划中时编辑必须给出明确反馈
系统 SHALL 在历史记录的训练日 id 不存在于当前训练计划时，提示该记录无法编辑，不得关闭弹层后毫无反应。

#### Scenario: 记录的训练日不在计划中
- **WHEN** 用户打开一条训练日 id 不在当前计划中的历史记录并点击「编辑这条记录」
- **THEN** 系统给出可读的提示说明该记录无法编辑，且不进入一个空白的训练页

### Requirement: 编辑不得丢失旧版本遗留字段
系统 SHALL 在编辑并保存历史记录时，保留该记录中旧版本的动作级备注、RIR 与疼痛字段。

#### Scenario: 编辑含动作级备注的旧记录
- **WHEN** 用户编辑一条动作上带有备注、RIR 与疼痛的历史记录并保存
- **THEN** 这些字段在保存后的记录里原样保留

#### Scenario: 编辑记录的疼痛值为奇数
- **WHEN** 用户编辑一条疼痛评分为奇数的记录
- **THEN** 疼痛评分向上取偶（1 取 2、9 取 10），保存后记录里的值为取偶后的值

### Requirement: 删除记录需确认且可回滚
系统 SHALL 在删除历史记录前向用户确认，删除失败时把记录恢复原状。

#### Scenario: 确认删除
- **WHEN** 用户在确认框中确认删除某条历史记录
- **THEN** 该记录从列表与统计中移除，并提示已删除

#### Scenario: 写盘失败
- **WHEN** 删除后写入本地存储失败
- **THEN** 该记录回到删除前的状态，不显示删除成功的提示

### Requirement: 详情、编辑与删除以所选记录本身为准
系统 SHALL 以用户选中的那条记录本身来定位详情、编辑与删除操作，不以 `id` 匹配结果为准；本地存储中存在重复 `id` 时，单条操作 SHALL 只影响被选中的那一条记录。当该记录对象因另一个标签页写入本地数据而被整体替换、对象引用不再指向当前记录时，系统 SHALL 依据该记录的标识与内容特征找回同一条记录，使操作仍然作用于用户所选的那一条。

#### Scenario: 点击重复 id 记录中的一条查看详情
- **WHEN** 本地存储中存在两条 `id` 相同的记录，用户点击历史列表中靠后的那一条
- **THEN** 弹层展示的是被点击的这一条记录的数据（日期、组数、容量与其列表行一致）

#### Scenario: 删除重复 id 记录中的一条
- **WHEN** 本地存储中存在两条 `id` 相同的记录，用户确认删除其中一条
- **THEN** 只有被选中的那一条被删除，另一条仍保留在列表与统计中

#### Scenario: 编辑重复 id 记录中的一条
- **WHEN** 本地存储中存在两条 `id` 相同的记录，用户编辑并保存其中一条
- **THEN** 只有被选中的那一条被更新，另一条保持原内容

#### Scenario: 跨标签页同步后删除所选记录
- **WHEN** 用户在标签页 A 打开了某条记录的详情弹层，标签页 B 写入本地数据使标签页 A 的记录对象被整体替换，用户随后在弹层里确认删除
- **THEN** 被选中的那一条记录从本地存储中移除并提示已删除，而不是提示「这条记录已经不在了」

#### Scenario: 跨标签页同步后保存对所选记录的编辑
- **WHEN** 用户在标签页 A 打开了某条记录的详情弹层并进入编辑，标签页 B 写入本地数据使标签页 A 的记录对象被整体替换，用户修改后保存
- **THEN** 被选中的那一条记录被更新为修改后的内容，另一条 `id` 相同的记录不受影响

### Requirement: 编辑有修改时离开页面必须给出提示
系统 SHALL 在用户编辑历史记录并做出修改后，于刷新、关闭或离开页面时触发浏览器原生的离开确认；未进入编辑、或编辑期间未做任何修改时 SHALL 不触发该提示。

#### Scenario: 编辑做过修改后刷新或关闭页面
- **WHEN** 用户编辑某条记录并修改了任意字段（重量、次数、勾选状态、RIR、疼痛、备注）后刷新或关闭页面
- **THEN** 浏览器弹出原生离开确认，提示更改可能不会保存

#### Scenario: 未修改或未进入编辑
- **WHEN** 用户未进入编辑，或进入编辑后没有修改任何字段就离开
- **THEN** 离开页面时不弹出离开确认

### Requirement: 缺少 id 的记录也能编辑且不生成重复记录
系统 SHALL 让缺少 `id` 的历史记录正常进入编辑态并按编辑处理：用户在详情弹层点「编辑这条记录」后进入的是编辑已存在的记录，而不是新建一条训练。保存后原记录被更新，训练历史中不出现内容重复的第二条记录。

#### Scenario: 编辑一条没有 id 的记录
- **WHEN** 本地存储中存在一条没有 `id` 的历史记录，用户在详情弹层点「编辑这条记录」并保存
- **THEN** 原记录被更新为修改后的内容，训练历史里该训练日与日期仍然只有一条记录，没有多出重复记录

#### Scenario: 没有 id 的记录在训练页显示为编辑
- **WHEN** 用户打开一条没有 `id` 的历史记录的编辑页
- **THEN** 训练页的主按钮显示「保存修改」而不是「完成训练」，离开页面时按编辑态给出未保存提示
