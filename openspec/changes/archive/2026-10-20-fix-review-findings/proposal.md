# Proposal

## Why

2026-10-20 对整个仓库做了一轮 review（测试 178/178 全绿、规格 5/5 通过的基线上），发现 5 个可操作缺陷：本地开发服务器可被畸形 URL 打崩、导入不校验记录 id 唯一导致「删除一条」实际删掉多条、测试运行器的自带服务器仍用裸 `startsWith` 判定路径穿越、进度页统计会把未来日期的记录算进「本周」并挤占图表槽位、编辑已完成记录时刷新/关页会静默丢弃全部修改。这些都属于正确性与数据安全问题，需要按 OpenSpec 流程先固化行为契约再修复。

## What Changes

- `scripts/serve.js`：畸形 percent-encoding 请求（如 `GET /%`）返回 400 而不是让进程因未捕获 `URIError` 退出。
- `tests/run.js`：自带静态服务器的路径穿越判定从裸 `startsWith(root)` 收紧为目录分隔符边界，与 `serve.js` 已修复的判定一致。
- 导入校验 `validateDB`：拒绝 `sessions` 中存在重复 `id` 的数据，导入失败时现有数据不变。
- 记录的删除与编辑改为按记录对象本身定位，不再按 `id` 匹配——即使本地存储被手改成存在重复 `id`，删除一条也只删这一条、编辑一条只写回这一条。
- 进度页统计与图表不计入训练日期晚于今天的记录（手改 localStorage 或旧备份导入的未来日期记录同样过滤），「本周训练」窗口收口到本周一至今天；开始表单的日期输入同时限制不得选未来日期。
- 编辑已完成记录且做过修改时，刷新/关闭/跳走触发浏览器原生 `beforeunload` 离开确认（「更改可能不会保存」）；未进入编辑或无修改时不做提示。已知限制：iOS Safari 与 PWA 独立窗口对该提示支持有限，此项按用户决策接受。

## Capabilities

### New Capabilities

- `progress-stats`: 进度页统计与图表的口径——按自然周汇总训练容量、统计本周/累计训练次数时对日期的有效性约定（本次先纳入「不计入未来日期记录」）。

### Modified Capabilities

- `dev-server`: 新增「畸形请求不得终止服务进程」要求；路径边界要求补充测试运行器自带服务器同样适用的场景。
- `local-data-integrity`: 导入校验新增「拒绝重复记录 id」场景。
- `session-history`: 删除/编辑的定位契约从「按 id」收紧为「按所选记录本身」（重复 id 场景）；新增「编辑有修改时离开页面必须提示」要求。
- `workout-draft`: 新增「开始训练只能选择今天或更早的日期」要求（草稿身份是 `训练日id@日期`，未来日期的草稿无意义）。

## Impact

- 代码：`scripts/serve.js`、`tests/run.js`、`js/progress.js`（`validateDB`、统计过滤）、`js/log.js`（删除/编辑定位、编辑模式脏标记与 `beforeunload`）、`index.html`（开始表单日期输入 `max`）。
- 测试：`tests/run.js` 需补对应回归用例（畸形 URL 400 且服务存活、重复 id 导入被拒、重复 id 只删所选记录、未来日期不进统计、编辑期离开提示）。
- 数据兼容：只收紧导入校验，不改动现有本地数据结构；已存的重复 id / 未来日期记录不被自动删除，仅被按新契约对待。
- 规格：`openspec/specs/` 下 3 个能力新增增量，1 个新能力 `progress-stats` 建立。
