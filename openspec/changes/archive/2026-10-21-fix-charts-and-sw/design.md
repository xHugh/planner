# Design

## Context

**周窗口**：`aggregateByWeek()`（`js/progress.js:28-41`）用 `Map` 按自然周起点聚合，没有训练的周根本不会成为键；`all.slice(-weeks)` 因此取回的是「最近 12 个**有训练**的周」。`drawBars()`（`:285-309`）再把柱子等距排布，于是 05/11 与 10/12 两根柱子紧挨着，6 周的停训在图上完全看不出来。图表副标题（`:134`）写的是「最近 12 周」。

**canvas 尺寸**：`paintBars()`（`:242-250`）在绘制时读一次 `canvas.clientWidth` 并据此设置位图缓冲 `canvas.width = W * dpr`。重绘只由 `drawBars()` 与 `themechange`（`:313-316`）触发，窗口尺寸变化时没有任何重绘，位图缓冲被 CSS 拉伸。另外绘制高度写死 `H = 180`，而样式表 `style.css:779` 写的是 `height: 190px`，每张图恒定纵向拉伸 5.6%。

**预缓存**：`sw.js:29-35` 用 `caches.addAll(ASSETS)`。Cache API 的 `addAll` 是全有全无的：任何一条请求失败，整个 Promise reject，`install` 事件失败，Service Worker 不激活。在 network-first 策略下，页面仍然能用，但离线能力整体消失，且失败原因不会出现在界面上。

**计划页徽标**：`app.js:11` 注入的计数函数调用 `sessionsOfDay(id)`（`js/log.js:22-24`），只按 `dayId` 过滤；进度页用的是 `countableSessions()`（`js/progress.js:46-49`），额外过滤了未来日期。同一条记录在两个页面上得到两个答案。`js/plan.js:55` 的「5 个训练日」是写死的字符串。

## Goals / Non-Goals

**Goals:**
- 图表显示的周窗口与它的说明文字一致，停训空档可见。
- 图表在任意视口尺寸下都按真实尺寸绘制。
- 单条资源失效不会让离线能力整体消失。
- 计划页与进度页对「训练次数」的口径一致。

**Non-Goals:**
- 不改 network-first 的缓存策略、不改缓存命名空间规则。
- 不引入图表库、不做响应式布局改造。
- 不追求「图表永远显示全部历史」——窗口宽度有限，取数规则以「最近」为准。

## Decisions

### 决策 1：周窗口以本周为终点，空周补 0，窗口内无数据时回退

窗口 = 截至本周的最近 12 个自然周，每周独立汇总，没有训练的周填 0。若这 12 周内没有任何训练而更早有训练，改用最近 12 个有训练的周（保持既有行为）作为回退，保证「有数据但图表空白」不会发生。图表说明文字显示实际使用的周数。

- 备选 A：始终用「最近 12 个有训练的周」并在中间插入 0（即把窗口固定在最后一次训练那一周）。否决——训练停止三周后，最后一次训练不再是「最近」的锚点，图上永远看不到「我现在停了几周」，而这正是用户开进度页最想知道的。
- 备选 B：窗口向前延伸到包含最近一次训练，周数可变。否决——周数不可控时柱宽与标签密度都随停训时长漂移，且说明文字无法给出一个稳定口径。
- 备选 C：保持现状，只把副标题改成「最近 12 个有训练的周」。否决——停训空档不可见是实质缺陷，改文案只是承认它。

### 决策 2：绘制高度取 canvas 的实际 CSS 高度，并在 `resize` 后防抖重绘

`paintBars()` 的高度改为 `canvas.clientHeight`（回退到 190），消除与样式表不一致造成的纵向拉伸。新增 `resize` 监听：防抖后对仍挂在页面上的 canvas 重绘。

- 备选：用 `ResizeObserver` 观察 canvas。否决——`resize` 事件已经覆盖「视口尺寸变化」这一实际场景，`ResizeObserver` 在本仓库的浏览器目标上收益有限而复杂度更高。

### 决策 3：预缓存逐条写入，失败只告警

`install` 里把 `addAll` 换成 `Promise.all(ASSETS.map(u => c.add(u).catch(warn)))`。失败的单条不阻断安装，其余资源照常缓存。

- 备选：保留 `addAll` 但在失败时重试。否决——重试解决不了「资源在服务器上已不存在」这种确定性失败，而逐条写入天然覆盖两种情况。
- 代价：清单里有一条失效资源时，用户在离线时会缺那一个文件——但至少其余页面可用，且 `console.warn` 留有线索。

### 决策 4：计划页徽标复用进度页的日期口径

`app.js` 注入计数函数时按 `s.date <= today()` 过滤，与 `countableSessions()` 同一规则；口径定义放在一处，调用方各自过滤。`plan.js:55` 的训练日数量改为 `PLAN.days.length` 现算。

## Risks / Trade-offs

- **窗口内有训练但更早的数据被挤出图表** → 接受：窗口口径是「最近」，更早的数据仍在累计容量、最佳组表与历史列表里可见；副标题写明周数，用户不会误以为那是全部数据。
- **`resize` 重绘在拖拽窗口时可能频繁触发** → 防抖 120ms；重绘只作用于仍连接在文档上的 canvas。
- **预缓存容错后，一条失效资源会被静默跳过** → 缓解：`console.warn` 记录是哪一条；`tests/run.js` 的 `offline` 组补一条「清单里每条路径都能取到 200」的断言，让失效在测试阶段暴露。
- **疼痛值超出 0–10 量程时按量程截断** → 超量程数据只可能来自手改或坏导入；截断后图仍在量程内，不再画出图表区域。
