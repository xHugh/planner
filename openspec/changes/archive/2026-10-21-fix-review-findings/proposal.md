# Proposal

## Why

全量 review 的最后一批问题集中在「规格与测试本身」：两处规格文本与实现对不上（照规格写测试会把正确实现判成 bug），六条规格场景零覆盖且恰好落在「写盘失败回滚」与「跨标签页」这两块最该有网的地方，两条测试断言同义反复（读起来像覆盖率，实际挡不住它们声称要防的回归），再加上导入确认文案、端口参数解析与文档漂移等零散问题。

## What Changes

- 规格措辞订正两处：奇数疼痛的取整方向（「就近吸附」→「向上取偶」）、空草稿清理的判据（以「草稿仍未被改动」为准，而不是「未勾选任何组」）。
- 导入前的覆盖确认说明现有记录与草稿都会被替换（实际行为一直是两者都替换，确认文案只说了记录）。
- 补齐 7 条零覆盖场景的回归用例：删除记录时写盘失败、放弃草稿时写盘失败、空闲时另一标签页删除记录、隔夜后继续草稿的 2 小时上限、未来周不挤占容量图槽位、全部记录都不可用、草稿的 RIR 缺失或不是有效数字。
- 两条同义反复的断言改成真观测：柱宽改为扫描 canvas 像素量出实际柱宽；预缓存清单改为在 Node 侧枚举磁盘上的运行时文件再比对，并补一条「清单里每条路径都能取到 200」。
- 断言卫生：确认框出现次数纳入断言、toast 断言前先清空文本、硬编码的种子日期改为相对今天。
- `scripts/serve.js` 的端口参数解析不再把 `0` 当假值（端口 0 交由系统分配随机端口）。
- 文档同步：`README.md` 与 `AGENTS.md` 补上实际存在但未记录的 `progress` / `devserver` 两个测试分组，并订正 `app.js` 的职责描述。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `session-history`: 需求「编辑不得丢失旧版本遗留字段」下的「疼痛值为奇数」场景措辞——「就近吸附到相邻的偶数档」在奇数上本就两邻等距、无法判定，改为明确「向上取偶（1→2、9→10）」。
- `workout-draft`: 需求「空草稿自动清理」的判据括注——括注写的是「未勾选任何组」，实现判据是「草稿仍处于未改动状态」，两者不等价（只写备注不勾组的草稿会被保留）。
- `local-data-integrity`: 需求「导入数据必须先校验后写盘」新增一条场景——覆盖确认必须说明草稿也会被替换，避免用户以为只替换记录。

## Impact

- 代码：`js/progress.js`（导入确认文案）、`scripts/serve.js`（端口解析）。
- 规格：`openspec/specs/session-history/spec.md`、`openspec/specs/workout-draft/spec.md`、`openspec/specs/local-data-integrity/spec.md`。
- 测试：`tests/run.js` 新增 7 条用例、替换 2 条断言、加固 3 处断言卫生、种子日期改为相对今天。
- 文档：`README.md`、`AGENTS.md`。
- 行为变更只有一处（导入确认文案多一句说明）；其余是规格措辞与测试覆盖，用户可观察到的训练数据行为不变。
