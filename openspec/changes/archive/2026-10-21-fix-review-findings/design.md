# Design

## Context

**规格文本与实现对不上的两处**：`session-history` 的「疼痛就近吸附到相邻的偶数档」——疼痛档位是 0/2/4/6/8/10，任何奇数到两邻都是等距，「就近」根本无法判定，而实现（`js/log.js:111-115` 的 `snapPain()`）明确是向上取偶；`workout-draft` 的「空草稿自动清理」括注写「未勾选任何组」，实现判据却是 `dr.touched === false && countDone(dr).done === 0`（`js/log.js:168`），只写备注不勾组的草稿会被保留。照这两条规格写测试，都会把正确实现判成缺陷。

**六条零覆盖的场景**：`删除记录时写盘失败`、`放弃草稿时写盘失败`（`workout-draft` 的「放弃草稿是唯一的丢弃入口」明确要求失败时草稿回到丢弃前状态）、`空闲时另一标签页删除记录`、`隔夜后继续草稿`（2 小时上限是防「10 小时训练」的唯一护栏，AGENTS.md 记着它曾以 `4320:01` 的形态出现过）、`未来周不挤占容量图槽位`、`全部记录都不可用`。前三条恰好是 `local-data-integrity` 能力存在的理由。

**两条同义反复的断言**：柱宽断言（`tests/run.js:1402-1408`）在测试里重算了 `js/progress.js:267` 的公式再断言 `>= 3`，从不读 canvas；预缓存清单断言（`tests/run.js:1602-1615`）把「运行时文件清单」写死在测试文件里，与 `sw.js` 的 `ASSETS` 一一对应，新加一个 `js/*.js` 却忘了加进 `ASSETS` 时断言照样绿，而离线会缺文件。

**断言卫生**：runner 自动接受所有 dialog，因此「删除前确认」「丢弃前确认」从未被断言；`toast` 的 `textContent` 从不清空（`js/core.js:109-114` 只切 `hidden` 类），同一页面里上一次的提示会被下一次断言误匹配；`tests/run.js:610-624` 的种子日期写死为 2026-10-14~17，违反仓库「用例不假设具体日期」的既有约定。

## Goals / Non-Goals

**Goals:**
- 规格文本与实现一致，测试按规格写就能通过。
- 规格里承诺的安全网（写盘失败回滚、跨标签页删除传播、2 小时上限）都有自动化用例守着。
- 断言真的在观测被测系统的行为，而不是复述被测系统的公式。

**Non-Goals:**
- 不改动训练数据的行为逻辑；除导入确认文案外，全部是规格措辞与测试覆盖。
- 不引入新的测试框架或依赖，仍用 `tests/run.js` 现有的 Playwright 运行器。

## Decisions

### 决策 1：规格按实现订正，实现不动

奇数疼痛改为「向上取偶」并补一组具体取值；空草稿清理的判据写成「草稿仍处于未改动状态、且未勾选任何组」，并新增一条场景把「只写备注不勾组」的保留行为写明。理由：实现的两个选择都是刻意做过的（`snapPain()` 的注释、AGENTS.md 对 `touched` 字段的说明），规格是描述行为的一方，应向既定行为收敛。

### 决策 2：柱宽断言改为扫描 canvas 像素

用 `getImageData` 逐列扫描非背景像素，取连续区间的宽度作为实际柱宽。代价是断言依赖渲染细节，但 canvas 的柱子是纯色渐变填充、背景是透明，扫描稳定。

- 备选：直接导出 `drawBars()` 用的数据并复算宽度。否决——那还是复述公式，与现状同类。

### 决策 3：预缓存清单断言改为枚举磁盘

runner 在 Node 侧用 `fs.readdirSync` 枚举 `js/`、`fonts/`、`icons/` 与根目录的运行时文件，与从 `sw.js` 里解析出的 `ASSETS` 比对；再补一条「清单里每条路径都能取到 200」，让失效条目在测试阶段暴露（这两条能互补：前者挡「漏加」，后者挡「失效」）。

### 决策 4：确认框与 toast 纳入断言

runner 在关键动作周围统计 dialog 次数，断言删除记录与放弃草稿各弹出 1 次确认框；toast 断言前先把 `#toast` 的文本清空，避免跨断言误匹配。这两处都只改测试，不改实现。

### 决策 5：种子日期一律相对今天

把写死的 2026-10-14~17 改成 `today()` 现算，与 `tests/run.js:1435-1444` 已有写法一致。

### 决策 6：端口参数按整数解析

`scripts/serve.js` 的端口解析从 `Number(...) || 8765` 改为先取数字再判断是否为整数，端口 0 保留（交由系统分配随机端口），其余非法值回落到 8765。

## Risks / Trade-offs

- **扫描 canvas 像素的断言可能受渲染实现影响** → 只在柱子是纯色、背景透明的场景下使用；若将来柱形改为描边或加了网格背景，需要调整扫描逻辑。
- **枚举磁盘的断言依赖仓库布局** → 新增运行时文件时会被这条断言提醒，正是它的目的；若将来有构建产物目录，需要把它排除在枚举范围外。
- **补 7 条用例会让测试时长增加** → 都是纯前端交互，不涉及网络等待；必要时可合并到同一条用例里断言多个点。
- **规格订正可能与用户的真实意图不符** → 两处都按实现写，并在场景里给出具体取值，便于后续发现意图不同再改。
