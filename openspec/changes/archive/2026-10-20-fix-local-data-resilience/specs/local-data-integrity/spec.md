# Spec Delta

## Purpose

定义本地训练数据（`localStorage` 键 `gym4.db.v1`）在读取、校验、写入、导入四个环节的完整性契约：结构异常的历史记录与草稿不得让任何页面崩溃，写盘失败必须如实反馈且不丢数据。

## ADDED Requirements

### Requirement: 结构异常的本地数据不得让页面崩溃
系统 SHALL 在读取本地数据后过滤掉结构不可用的历史记录与草稿，使记录页、训练页、进度页在任何本地数据形态下都能完成渲染，不得因数据缺字段而抛出未捕获异常。

#### Scenario: 历史记录的动作缺 sets
- **WHEN** 本地存储中存在某条历史记录，其动作缺少 `sets` 数组
- **THEN** 记录页与进度页正常渲染，该记录不进入历史列表与统计，并显示「N 条记录格式异常已跳过」的提示

#### Scenario: 历史记录的 sets 元素为 null
- **WHEN** 本地存储中存在某条历史记录，其某个动作的 `sets` 数组里含 null 元素
- **THEN** 记录页与进度页正常渲染，该记录不进入历史列表与统计，并计入「格式异常」提示

#### Scenario: 草稿的动作 sets 元素为 null
- **WHEN** 本地存储中存在某份草稿，其某个动作的 `sets` 数组里含 null 元素
- **THEN** 记录页正常渲染，坏草稿被清理且不显示在「未完成的训练」里，打开训练页不抛出异常

#### Scenario: 草稿缺少 moves
- **WHEN** 本地存储中存在缺少 `moves` 的草稿
- **THEN** 记录页正常渲染，该草稿被清理，不留下既看不见也删不掉的僵尸草稿

### Requirement: 存储容器结构异常时退化为空集合
系统 SHALL 校验本地数据中 `sessions` 与 `drafts` 的容器类型；类型不符时按空集合处理并继续启动，不得让页面在渲染时抛错。

#### Scenario: sessions 不是数组
- **WHEN** 本地存储中的 `sessions` 是对象而非数组
- **THEN** 计划页、记录页、进度页均能完成渲染，不出现未捕获异常

#### Scenario: drafts 不是对象
- **WHEN** 本地存储中的 `drafts` 是字符串而非对象
- **THEN** 记录页正常渲染，不出现未捕获异常

### Requirement: 写盘失败必须如实反馈且不丢数据
系统 SHALL 在写入本地存储失败时保留原有数据、向用户提示失败，并且不把失败的操作显示为成功。

#### Scenario: 完成训练时配额已满
- **WHEN** 写入本地存储抛出异常
- **THEN** 显示「存储失败」提示，训练页保持打开，本次训练不计入历史记录，用户可稍后重试

#### Scenario: 删除记录时写盘失败
- **WHEN** 删除某条历史记录后写入本地存储失败
- **THEN** 该记录回到删除前的状态，不显示删除成功的提示

### Requirement: 导入数据必须先校验后写盘
系统 SHALL 在导入 JSON 前校验其结构，校验不通过时拒绝导入、不改动现有数据、不写盘。

#### Scenario: 导入结构非法的数据
- **WHEN** 导入的 JSON 中 `sessions` 不是数组，或某条记录缺 `id`、`date` 格式不对、动作缺 `sets`，或 `rir`/`maxPain`/`durationMin` 不是数字
- **THEN** 显示失败原因并说明是哪一项不合法，现有记录保持不变

#### Scenario: 导入结构合法的数据
- **WHEN** 导入的 JSON 通过全部结构校验且用户确认覆盖
- **THEN** 现有记录与草稿被替换，进度页重新渲染并提示导入成功
